# コンセプト設計支援 - 機能改善・追加提案

## 現状の課題まとめ

### 課題1: 成長スコアの算出根拠が薄い（投稿データ不足）
キーワード検索で見つかったアカウントは**検索結果の1投稿のみ**がDBに保存され、
その1投稿の数値だけで `avg_likes`, `account_age_days`, `growth_score` が算出されている。

**例:** アカウント開設3ヶ月、実際は過去投稿50件あるが、DB上は1件のみ。
→ `total_post_count=1`, `earliest_post_at=その1件の投稿日`（本来より新しい日付）
→ `account_age_days` が過小 → `followers_per_day` が過大 → `growth_score` が実態と乖離

### 課題2: 成長スコア計算式のコンセプト設計適合度
コンセプト設計の指南書では「直近で異常に伸びているアカウント」を探す。
現在の `growth_score = follower_density × eng_quality` は方向性は正しいが:
- `account_age_days` の精度が低い（参加日より投稿日ベース）
- 投稿数が少なくてもスコアが出る（信頼性低）
- リプライ数（コメント）のウェイトが含まれていない

### 課題3: 指標の説明がない
画面上に「成長スコア」「ER」「バズ」の意味が一切表示されない。

### 課題4: 不要なアカウント情報のノイズ
企業アカウント、古参アカウント、一時的なバズ等がランキングに混在。

---

## 改善提案

### 提案A: 「深掘りスキャン」機能（投稿不足の自動補完）【優先度: 高】

**概要:** 投稿データが不足している（3件以下の）アカウントに対して、
自動的に過去投稿を取得し、成長スコアの精度を上げる。

**実装方法:**
1. 新コマンド `th_buzz_deep_scan` を作成
   - DBから `total_post_count <= 3` かつ `followers_count IS NOT NULL` のアカウントを取得
   - 各アカウントに対して `fetch_author_posts()` + `update_growth_stats()` を実行
   - ブラウザを1回だけ起動してループ処理（効率化）
   - 処理上限（例: 1回あたり最大10アカウント）を設定
2. 急成長ランキング画面に「深掘りスキャン」ボタンを追加
   - 「投稿不足のアカウント N件を深掘りスキャンする」と表示
   - ジョブとして実行、ステータスポーリング
3. ER/バズ判定一括再計算の後に自動で呼ぶオプション

**効果:** 成長スコアの算出根拠となる `avg_likes`, `avg_replies`, `account_age_days` が
実際の投稿データに基づくものになり、信頼性が大幅に向上。

### 提案B: 成長スコア計算式の改善【優先度: 高】

**現在の計算式:**
```
follower_density = followers_count / account_age_days
eng_quality = min((avg_likes / followers_count) * 100, 50.0)
growth_score = follower_density * eng_quality
```

**改善案:**
```
# 1. account_age_days を参加日ベースに改善
if joined_at:
    account_age_days = (now - joined_at).days
else:
    account_age_days = (now - earliest_post_at).days  # フォールバック

# 2. エンゲージメント品質にリプライも加味
eng_quality = min(((avg_likes + avg_replies * 2) / followers_count) * 100, 50.0)

# 3. 投稿数による信頼度係数（5投稿未満はペナルティ）
confidence = min(total_post_count / 5, 1.0)

# 4. 最終スコア
growth_score = follower_density * eng_quality * confidence
```

**改善ポイント:**
- `joined_at`（「このプロフィールについて」から取得済み）を優先 → アカウント年齢の精度向上
- `avg_replies * 2` を加味 → リプライはより深いエンゲージメントの指標
- `confidence` 係数 → 投稿数が少ない段階ではスコアを割引し、投稿データが充実してから正確なスコアを反映
- 投稿数5件以上で confidence=1.0 → 深掘りスキャン後に正しいスコアが反映される

**コンセプト設計との整合:**
- 「開設1ヶ月でフォロワー1万人」→ `followers_per_day` が高い = `follower_density` が高い ✓
- 「投稿のエンゲージメントが高い」→ `eng_quality` が高い ✓
- 「最近作られたアカウント」→ `account_age_days` が小さい = `follower_density` が高い ✓

### 提案C: ヘルプ画面（モーダル）の追加【優先度: 高】

**概要:** 急成長アカウントランキング画面のタイトル横に「?」ヘルプアイコンを設置。
クリックでモーダルを表示。左ナビ形式で以下のセクション:

**セクション構成:**

#### 1. コンセプト設計の考え方
- **Step 1: 直近で異常に伸びているアカウントを見つける**
  - 「初投稿で10万imp」「開設1週間でフォロワー3000人」等の基準
  - このツールでは「成長スコア」でソートして上位を確認
  - 「アカウント日数」で若いアカウントに絞り込み
- **Step 2: 伸びている要因をピックアップする**
  - 投稿者詳細画面で投稿内容・バズ投稿・ピン留め投稿を分析
  - bio、表示名、投稿のトーン、使用メディア（画像/動画）をチェック
  - 「何がウケているのか」を3つ以上ピックアップ
- **Step 3: ピックアップした要素を少しずらしてコンセプトを固める**
  - 伸びている要因は残しつつ差別化
  - 丸パクリではなく「ずらし」が重要

#### 2. 指標の説明
- **成長スコア** = フォロワー密度 × エンゲージメント品質 × 信頼度
  - フォロワー密度: 1日あたりのフォロワー数（フォロワー数 ÷ アカウント日数）
  - エンゲージメント品質: 平均いいね÷フォロワー数 ×100（上限50）
  - 信頼度: 投稿データの充実度（5投稿以上で1.0）
  - 「短期間でフォロワーが多く、かつエンゲージメントが高い」→ 高スコア
- **ER（エンゲージメント率）** = (いいね + リプライ + リポスト) ÷ フォロワー数 × 100
  - フォロワーに対してどれだけ反応があるかの指標
  - フォロワーが少なくても高ERなら「刺さるコンテンツ」を持っている証拠
- **バズ判定** = フォロワー規模別の閾値を超えたかどうか
  - micro(〜1万): いいね500以上 or リプライ50以上 かつ ER 5%以上
  - mid(〜10万): いいね5000以上 or リプライ200以上 かつ ER 3%以上
  - macro(10万+): いいね50000以上 or リプライ1000以上 かつ ER 2%以上
- **エンゲージメントスコア（投稿単位）** = いいね×1.0 + リプライ×3.0 + リポスト×2.5
  - リプライが最も重み付けが高い（深いエンゲージメントの指標）

#### 3. このツールの使い方ガイド
- リサーチの手順（キーワード検索 → ランキング確認 → 深掘り → 分析）
- 各画面の役割説明

### 提案D: 「コンセプト候補」自動判定フラグ【優先度: 中】

**概要:** コンセプト設計の参考になりそうなアカウントを自動判定し、
不要なアカウントをフィルタリングする。

**実装方法:**
1. `THBuzzAuthor` に `is_concept_candidate` BooleanField 追加
2. 判定条件（デフォルト、画面から閾値調整可能）:
   - `account_age_days <= 90` AND `account_age_days >= 7`（1週間〜3ヶ月以内）
   - `followers_count >= 500`
   - `followers_per_day >= 10`（1日10人以上のペース）
   - `growth_score >= 一定閾値`
3. 判定タイミング:
   - `update_growth_stats()` 実行時に自動判定
   - 深掘りスキャン後に再判定
4. 急成長ランキング画面に「候補のみ」フィルタ追加
5. バズ投稿取得画面のキーワード検索時に「候補条件に合わないアカウントはスキップ」オプション

**お気に入りとの違い:**
- `is_favorited`: ユーザーが手動で選択（分析済み・参考にしたいアカウント）
- `is_concept_candidate`: システムが自動判定（分析対象の候補）

---

### 提案E: キーワード検索時の「急成長フィルタ」オプション【優先度: 中】

**概要:** バズ投稿取得画面やキーワード一括巡回時に、
「成長候補に該当しないアカウントの投稿は保存しない」オプションを追加。

**実装方法:**
1. 検索フォームに「急成長フィルタ」チェックボックスを追加
2. フィルタON時: 各投稿のアカウントについて:
   - 既存アカウント: `is_concept_candidate=True` の場合のみ投稿を保存
   - 新規アカウント: プロフィール取得 → 条件判定 → 候補の場合のみ投稿保存
3. これにより、DBに保存されるデータが「参考になるアカウント」に限定され、
   ノイズが大幅に減少

**注意点:**
- 初回は全アカウントのプロフィール取得が必要（候補判定のため）
- 処理時間は増えるが、保存データの質は向上

類似の急成長アカウントを自動探索。

**実装方法:**
1. お気に入りアカウントのbio/投稿文からキーワードを自動抽出
2. そのキーワードで自動検索 → 急成長フィルタで候補を抽出
3. 「この人と似ている急成長アカウント」として表示
