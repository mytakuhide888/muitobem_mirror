# リサーチ機能の検証と改善提案

> 対象: muitobem バズリサーチ機能
> 作成日: 2026-02-23
> 根拠: コードベース全体の精査 + `CLAUDE/strategy/fortune_business_strategy.md` の事業目標

---

## 1. 現行リサーチフローの検証

### 1.1 現在のフロー（実態）

```
[手動] キーワードを考える
  → [手動] バズ投稿取得 or キーワード一括巡回を実行
  → [自動] 投稿取得 + 投稿者プロフ取得 + 成長スコア算出 + 占い適合分類
  → [手動] ランキング画面で目視確認、フィルタ操作
  → [手動] 気になるアカウントを個別クリック → 投稿者詳細画面
  → [手動] 投稿を1つずつ読んで伸びている要因を頭の中で分析
  → [手動] メモ欄にテキストで感想を書く
  → [手動] お気に入り/対象外をトグル
  → （繰り返し）
```

### 1.2 目的との適合度評価

**目的**: メイト氏3ステップ（①急成長垢を見つける → ②伸びている要因を3つ以上ピックアップ → ③少しずらしてコンセプトを固める）をシステムで実現する。

| ステップ | 現在の対応状況 | 評価 |
|---------|-------------|------|
| ① 急成長垢の発見 | ✅ 成長スコア・品質スコア・コンセプト候補自動判定が動作 | **〇 基盤はある** |
| ② 伸びている要因のピックアップ | ❌ 投稿の一覧表示のみ。要因分析は完全手動 | **✗ ボトルネック** |
| ③ ずらしてコンセプト設計 | ❌ 機能なし。メモ欄がテキストのみ | **✗ 未対応** |

**結論**: ①の「発見」は機能している。問題は②③が完全に手動であること。リサーチ工数の8割が②の「投稿を読んで要因を考える」作業に費やされている。

### 1.3 現行フローの具体的なボトルネック

#### ボトルネック A: 発見の網羅性不足
- **キーワード依存**: 「占い」「タロット」で検索しても、独自の言い回しをする急成長垢を取りこぼす
- **Threads限定**: 戦略上はThreads + Instagram両輪だが、Instagram側のリサーチ機能がゼロ
- **横展開なし**: お気に入り垢Aを見つけても「Aに似た急成長垢」を自動で探せない

#### ボトルネック B: 深掘り分析の労力
- 1アカウントの分析に15〜30分かかる（投稿を10〜50件読む → パターンを抽出）
- 分析観点が属人的（何を見るべきか毎回思い出す必要がある）
- 投稿内容のテキスト分析は人間が全件読む前提

#### ボトルネック C: 知見の蓄積と比較ができない
- メモ欄はフリーテキスト → 構造化されていない → 後から横断検索・比較不可
- 「この垢とあの垢の共通点は？」を出すには2つのブラウザタブを開いて目視比較
- コンセプト設計の「ずらし」作業を支援する機能がない

## 2. 自動化と精度向上のための改善フロー提案

### 2.1 目指すべきフロー

```
[週次自動] 登録キーワード群で一括巡回 → 新規アカウント自動発見
  → [自動] 占い適合スコアで自動フィルタ（非占い垢を除外）
  → [自動] 成長スコア閾値超えを「要注目」としてフラグ
  → [自動] 要注目垢の過去投稿を自動取得（深掘りスキャン自動実行）
  → [自動] 投稿パターン分析（時間帯・形式・テーマ・バズ傾向を自動集計）
  → [自動] 導線分析（bio内リンク・マネタイズシグナルの構造化）
  ────────────────────────────────────
  ここから人間の判断
  ────────────────────────────────────
  → [半自動] 「要分析」リストから選んで構造化メモを記入（チェックリスト形式）
  → [半自動] 複数アカウント比較画面で共通パターンを可視化
  → [半自動] コンセプト設計ワークシートで「ずらし」を言語化
```

### 2.2 自動化すべき範囲と人間が判断すべき範囲

| 処理 | 自動化 | 理由 |
|------|--------|------|
| キーワード巡回の定期実行 | ✅ | 毎日/週次で回すべき。手動だと忘れる |
| 非占い垢の除外 | ✅ | fortune_classifier が既に動作。精度向上の余地あり |
| 深掘りスキャン自動実行 | ✅ | 成長スコア閾値超えのアカウントは自動で過去投稿取得 |
| 投稿のテーマ・形式分析 | ✅ | テキスト/画像/動画の比率、投稿時間帯、テーマ分類は自動化可能 |
| 導線構造の抽出 | ✅ | bio内のURL・LINE・STORES等は自動検出済み。構造化表示を追加 |
| 「なぜ伸びているか」の判断 | ❌ | 人間の解釈が必要。ただしチェックリストで観点を固定化できる |
| コンセプトの「ずらし」方向 | ❌ | 創造的判断。ワークシートで思考の型を提供 |
| 最終的なコンセプト決定 | ❌ | 事業判断 |

## 3. 現状機能で不足している観点

### 3.1 【高優先】投稿パターン自動分析

**現状**: 投稿は取得・表示しているが、パターン抽出は手動。
**不足**: 以下の観点が自動集計されていない。

| 分析観点 | 現状 | あるべき姿 |
|---------|------|-----------|
| 投稿時間帯分布 | ❌ | ヒートマップ表示（何曜日の何時に投稿が多いか） |
| メディア形式比率 | ❌ | テキストonly / 画像付き / 動画付き / カルーセルの比率 |
| バズ投稿の共通テーマ | ❌ | バズ投稿（is_viral=True）のテキストから頻出テーマを抽出 |
| 投稿テキスト長の傾向 | ❌ | 短文中心か長文中心か、バズ投稿の平均文字数 |
| ハッシュタグ使用パターン | ❌ | よく使うタグ、バズ投稿のタグ傾向 |
| エンゲージメント推移 | ❌ | 直近のER推移（成長中 / 安定 / 下降のトレンド） |

**実装イメージ**: `THBuzzAuthor` の投稿者詳細画面に「分析タブ」を追加。既存の投稿データを集計するだけなのでDB変更は最小限。

### 3.2 【高優先】構造化メモ（分析チェックリスト）

**現状**: `memo` がTextField。何を書くかは毎回ユーザーが考える。
**不足**: メイト氏Step2「伸びている要因を3つ以上ピックアップ」を構造的に記録する仕組みがない。

**提案モデル**:
```
THBuzzAuthorAnalysis（新規モデル）:
  author          → THBuzzAuthor FK
  # ─── 伸びている要因チェックリスト ───
  factor_profile     : テキスト  # プロフィール/表示名の工夫
  factor_concept     : テキスト  # コンセプト（何者か、ギャップ）
  factor_content     : テキスト  # 投稿内容の傾向
  factor_format      : テキスト  # 投稿形式（テキスト/画像/動画の使い分け）
  factor_frequency   : テキスト  # 投稿頻度・タイミング
  factor_engagement  : テキスト  # エンゲージメントの取り方（返信の仕方等）
  factor_funnel      : テキスト  # 導線設計（bio→LINE→鑑定等）
  factor_other       : テキスト  # その他の要因
  # ─── メタ情報 ───
  overall_assessment : テキスト  # 総合評価
  concept_inspiration: テキスト  # この垢から得たコンセプトのヒント
  differentiation_idea: テキスト # ずらしのアイデア
  analyzed_at        : DateTime  # 分析日時
```

**UI**: 投稿者詳細画面に「分析記録」タブを追加。各項目をテキストエリアで記入。

### 3.3 【高優先】定期自動巡回パイプライン

**現状**: `th_buzz_run_scheduled` はPENDINGジョブの実行のみ。定期巡回は手動でジョブ登録が必要。
**不足**: 「毎日決まったキーワードで巡回し、新規発見→深掘りまで自動で回す」パイプラインがない。

**提案**:
```
新規管理コマンド: th_buzz_auto_pipeline
  1. 登録済みキーワードセットで keyword_scan を実行
  2. 新規発見された占い適合スコア30以上のアカウントを抽出
  3. そのうち投稿数3件以下を自動で deep_scan
  4. 成長スコア閾値超え（例: 100以上）のアカウントを「要注目」フラグ
  5. 結果サマリをログ出力（または管理画面ダッシュボードに表示）
```

schedulerのcronに1日1回で登録。

### 3.4 【中優先】アカウント比較機能

**現状**: 1アカウントずつ詳細画面を開く。横断比較は不可。
**不足**: お気に入り複数アカウントを並べて「共通点」「差異」を一覧で見る機能。

**提案画面**: `/console/buzz-compare/`
- お気に入り or チェックボックス選択した2〜5アカウントを横並び表示
- 比較項目: bio、フォロワー数、成長スコア、投稿形式比率、バズ投稿テーマ、導線構造、マネタイズシグナル
- 共通キーワードをハイライト

### 3.5 【中優先】類似アカウント自動発見

**現状**: 新しいアカウントの発見は常にキーワード検索起点。
**不足**: 「お気に入りアカウントAに似た急成長垢」を自動で探す機能。

**実装方針**: 
1. お気に入りアカウントのbio + バズ投稿テキストからキーワードを自動抽出
2. そのキーワードで追加検索を実行
3. 占い適合スコアと成長スコアでフィルタ
4. 既知アカウントを除外して新規発見を提示

### 3.6 【低優先・将来】Instagram側リサーチ

**現状**: Threads限定。Instagram Graph APIはスタブ状態（完成度20%）。
**不足**: Instagramの競合リサーチ機能。

ただし、これは実装コストが大きい。**当面はThreads側のリサーチを完成させ、Instagram側は手動リサーチで補完する方針を推奨**。理由:
- ThreadsとInstagramは同一運営者が多い（Threads垢→Instagramプロフからリンクで辿れる）
- Threads側の急成長 = Instagram側でも伸びている可能性が高い
- Instagram Graph APIは認証フローが複雑で、スクレイピングもBAN対策が厳しい

## 4. 機能実装の優先提案

### 4.1 即効性の高い3機能（Phase A: 1〜2週間）

これらは既存データと既存UIの拡張で実現でき、リサーチ効率を大幅に改善する。

#### 機能①: 投稿パターン分析ダッシュボード

**場所**: 投稿者詳細画面に「📊 分析」タブを追加

**表示内容**:
- 投稿時間帯ヒートマップ（曜日 × 時間帯、既存 `posted_at` から算出）
- メディア形式の円グラフ（text / image / video / carousel、既存 `media_type` から算出）
- バズ投稿（`is_viral=True`）の文字数分布
- ER推移の折れ線グラフ（直近投稿のERを時系列で表示）
- 頻出ワードクラウド（投稿テキストからストップワード除去後の頻出名詞）

**工数**: 小〜中。DB変更なし、既存データの集計ロジックとChart.js表示のみ。

#### 機能②: 構造化分析メモ

**場所**: 投稿者詳細画面に「📝 分析記録」タブを追加

**モデル追加**: `THBuzzAuthorAnalysis`（上記3.2参照）

**UI**: 
- 8項目のテキストエリア（プロフ、コンセプト、投稿内容、投稿形式、頻度、エンゲージ、導線、その他）
- 「総合評価」「コンセプトのヒント」「ずらしアイデア」の3欄
- 保存ボタンで即時DB保存
- 分析済みフラグがランキング画面に表示される

**工数**: 小。モデル1つ + テンプレート1タブ + View/API 2〜3本。

#### 機能③: 自動巡回パイプライン

**場所**: 新規管理コマンド `th_buzz_auto_pipeline` + schedulerに登録

**動作**:
1. 定義済みキーワードセット（占い/タロット/霊視/ツインレイ/金運/恋愛占い/スピリチュアル）で巡回
2. 新規発見アカウントを自動で深掘りスキャン（投稿数3件以下のもの）
3. 成長スコア100以上 + 占い適合スコア30以上を「要注目」フラグ（新規 `is_attention_needed` フィールド）
4. ダッシュボード（ランキング画面上部）に「今週の新規発見: X件、要注目: Y件」を表示

**工数**: 中。コマンド1つ + scheduler設定 + ランキング画面に集計表示。

### 4.2 リサーチ精度を高める2機能（Phase B: 2〜4週間）

#### 機能④: アカウント比較画面

**場所**: `/console/buzz-compare/`

**操作**: ランキング画面のチェックボックスで2〜5件選択 → 「比較」ボタン

**表示**:
- 横並びカード（bio、フォロワー、スコア群）
- 投稿パターン比較（時間帯、形式、頻度を並列表示）
- マネタイズシグナルの比較
- 構造化メモの比較（分析記録がある場合）
- **共通パターンの自動検出**（bio内の共通キーワードをハイライト）

#### 機能⑤: 類似アカウント自動発見

**場所**: 投稿者詳細画面に「🔍 類似アカウントを探す」ボタン

**動作**:
1. 対象アカウントの bio + バズ投稿トップ5からキーワードを自動抽出（名詞・固有名詞）
2. 抽出キーワードのうち占い関連度が高いもの上位3つで Threads検索を実行
3. 既存DBにないアカウントをプロフィール取得 → スコア算出
4. 類似度スコア順で結果を表示

## 5. 実装の推奨順序と理由

```
Phase A（即効性: 1〜2週間）
  ③ 自動巡回パイプライン  ← 最優先。手動トリガーを排除
  ② 構造化分析メモ        ← Step2の作業品質を安定化
  ① 投稿パターン分析      ← 「なぜ伸びているか」の判断材料を自動提供

Phase B（精度向上: 2〜4週間）
  ④ アカウント比較         ← 共通パターンの発見効率化
  ⑤ 類似アカウント発見     ← 発見の網羅性向上
```

**Phase Aを完了すれば**:
- 毎朝ダッシュボードを開くだけで新規発見アカウントが並んでいる
- 気になるアカウントを開けば投稿パターンが自動分析済み
- 構造化メモで分析結果を蓄積、後から横断検索・比較可能
- リサーチ工数は現在の **1/3〜1/5** に削減される見込み

## 6. 補足: 現行のfortune_classifierの改善余地

現行の `fortune_classifier.py` は**キーワードマッチ方式**で、精度は実用レベル。ただし以下の改善が可能:

1. **bio内のURL解析追加**: `stores.jp`, `lin.ee`, `linktr.ee` 等のドメインでマネタイズ度を加算（現在はテキスト内「STORES」等の文字列マッチのみ）
2. **投稿テキストの加重改善**: 現在は投稿数で平均化しているが、直近投稿の重みを大きくすべき（ジャンル転換したアカウントを正しく評価）
3. **フォロワー/投稿比率による信頼度補正**: フォロワー数に対して投稿数が極端に少ない場合（買いフォロワー疑惑）をペナルティ

これらはPhase Aの③自動巡回パイプライン実装時に合わせて対応すると効率的。
