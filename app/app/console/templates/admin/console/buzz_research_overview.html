バズ・人気アカウントリサーチ

Threads 上の伸びているアカウントを巡回スクレイピングし、コンセプト設計の素材を集めるための運用入口。

📌 通常フェーズの運用手順

このページは、Threads のリサーチをほぼ無人で回しつつ、人間は 異常監視と方針判断のみ 行うための窓口です。

  1. 日 1〜数回、「① バズキーワードスキャン」を開いて巡回を実行 — キーワード（例:「占い」「タロット」）を入力 → 「実行」ボタン。
    新規バズ投稿・成長中のアカウントが自動でデータベースに蓄積されます。
  2. 「② スクレイピングログ」で WARN 以上のイベントを毎日チェック — 通常時は 0 件のはず。LOGIN_FAILED / HTTP_403 / HTTP_429 / SUSPENSION_DETECTED が出ていたら即対応（後述の対応表参照）。
  3. 「③ リサーチ用アカウントのステータス・カウンタ」で現役リサーチ垢（arayahide3 等）が ACTIVE のまま稼働しているか確認 — daily_request_count が当日上限内、status が SUSPENDED に落ちていないことを確認。
  4. 通知メール（ebisu.uranai@gmail.com）の異常受信を確認 — WARN 以上のイベント発生時は Gmail に自動送信されます。30 分以内に同種イベントが 3 件以上なら 1 通にまとめて配信。

頻度の目安（通常フェーズ）： 巡回スキャン = 日 1〜3 回／ログチェック = 日 1 回（朝）／アカウント状態確認 = 日 1 回。

運用画面（サブメニュー）

①バズキーワードスキャン

キーワードを入力して Threads を巡回 → バズ投稿・成長アカウントを取得。
ステータスに応じてレート制限（VPS_WARMUP=5 req/h、ACTIVE=15 req/h）が自動適用されます。

→ 一括巡回を開く

②スクレイピングログ

LOGIN_FAILED / HTTP_403 / HTTP_429 / SUSPENSION_DETECTED 等のイベントを時系列で確認。
list_filter で event_type／level／notified（通知済み）でフィルタできます。

→ ScraperEventLog 一覧を開く

③リサーチ用アカウントの状態

arayahide3 等のステータス・日次カウンタ・最終使用時刻を確認。
「ACTIVE に昇格」「VPS_WARMUP に戻す」「SUSPENDED 解除」のアクションも提供。

→ ResearchAccount 一覧を開く

④通知設定

メール宛先（カンマ区切り可）／通知イベント種別／通知レベル下限／集約しきい値／自動停止の設定。

→ ScraperNotificationConfig を開く

📎 補足：観察フェーズ（新規アカウント追加後 1〜2 週間）について
新規リサーチアカウントを追加した直後は status=VPS_WARMUP の 超低頻度モード（5 req/h、待機 60〜180 秒、深夜停止 22:00〜09:00、日次 30 req、スクロール 3 回）で稼働します。

観察フェーズ中の推奨運用：
  • 巡回頻度：1 日 1 回のみ（午前か夕方）。連続実行は控える。
  • 毎日 1 回、「② スクレイピングログ」で WARN+ イベントゼロを確認。
  • 毎日 1 回、「③ リサーチ用アカウントの状態」で SUSPENDED に落ちていないことを確認。
  • 14 日間（warmup_duration_days）連続無凍結なら、次回スクレイパ起動時に maybe_auto_promote() が走り自動で ACTIVE 昇格。
  • 異常が出たら即「③」から該当アカウントを SUSPENDED にし、原因調査。プロキシ／頻度／UA のいずれかを見直す。
観察フェーズで 2〜4 週連続無凍結を確認したら、Phase F（投稿アカウントの立ち上げ）に進める段階です。
